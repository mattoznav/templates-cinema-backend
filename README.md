# Cinema template: Backend

The API behind the cinema website, the admin back office and the customer app: movies, halls, showtimes, seat maps, bookings, tickets and payments.

Django 6.1 and Django REST Framework. Part of the [`templates-cinema`](https://github.com/mattoznav/templates-cinema) template, inside the [`templates`](https://github.com/mattoznav/templates) collection.

## Quick start

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
.venv/bin/python manage.py bootstrap
.venv/bin/python manage.py runserver
```

The API is at `http://localhost:8000/api/` and the Django admin at `http://localhost:8000/admin/`.
To get an admin user, set `DEMO_ADMIN_PASSWORD` in `.env` before running `bootstrap`, or run `manage.py createsuperuser`.

Run the tests with `.venv/bin/python manage.py test`.

## Data: CSV files instead of a database server

There is no database to install. The files in [`data/`](data) are the tables:

| File | Table |
| --- | --- |
| `venue.csv` | The cinema: name, address, timezone, currency |
| `genres.csv`, `movies.csv`, `movie_genres.csv` | Catalogue and the genre join table |
| `halls.csv`, `seat_types.csv`, `seats.csv` | Screens and their seats |
| `ticket_types.csv` | Adult, reduced, child prices |
| `showtimes.csv` | Programming, stored as days from today |

`manage.py bootstrap` creates a local SQLite file in `var/` (ignored by git) and fills it from the CSV files.
Bookings, payments and users live only in that file: run `manage.py load_data` to reset the demo to the CSV contents.

The CSV files are read, never written: seat booking needs transactions and constraints that plain files cannot give.
To go to production, set `DATABASE_URL` (for example `postgres://user:password@host:5432/cinema`): nothing else changes.

### Regenerating the data

```bash
python tools/build_catalog.py   # movies from Wikidata and Wikipedia
python tools/build_schedule.py  # seats and two weeks of showtimes
```

Showtimes use a `day_offset` column, so the demo always shows the next 14 days whenever it is loaded.

### Data sources and licenses

- Movie facts (titles, dates, runtimes, genres, credits, trailers) come from [Wikidata](https://www.wikidata.org), available under [CC0](https://creativecommons.org/publicdomain/zero/1.0/).
- Synopses are the lead paragraphs of the English Wikipedia articles, available under [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/). Each movie keeps its article in `source_url`: show it next to the synopsis to give attribution.
- Posters are generated by the API (`/api/movies/<slug>/poster.svg`). Real posters are copyrighted and are not included.
- Venue, halls and prices are fictional.

## Booking and payment flow

1. `POST /api/bookings/` holds the seats for 10 minutes (`BOOKING_HOLD_MINUTES`) and returns a pending booking.
2. `POST /api/bookings/<id>/checkout/` creates a payment and returns the `client_secret`.
3. The client completes the payment; the provider reports the outcome to the backend.
4. On success the booking is confirmed and one ticket per seat is issued. Unpaid holds expire and their seats are freed.

Edge cases are handled on purpose: two people can never hold the same seat (a database constraint, not just a check), duplicate webhooks are ignored, a payment that arrives after the hold expired is kept if the seats are still free and refunded otherwise.

### Payment providers

| `PAYMENT_PROVIDER` | Use it for |
| --- | --- |
| `fake` (default) | Demos and development. No account, no keys, no money. The client "pays" with `POST /api/payments/fake/complete/` (`{"payment_id": 1, "outcome": "succeeded"}` or `"failed"`). |
| `stripe` | Real payments with [Payment Intents](https://docs.stripe.com/payments/payment-intents). Selected automatically when `STRIPE_SECRET_KEY` is set. |

To try Stripe without moving money, use the test mode keys from the Stripe dashboard and the [test cards](https://docs.stripe.com/testing).
Locally, forward webhooks with the Stripe CLI:

```bash
stripe listen --forward-to localhost:8000/api/payments/stripe/webhook/
```

and put the `whsec_...` secret it prints in `STRIPE_WEBHOOK_SECRET`.

## API

Public reads, authenticated bookings, staff-only writes. Authentication uses JWT: send `Authorization: Bearer <access token>`.

| Method | Path | Who | What |
| --- | --- | --- | --- |
| GET | `/api/venue/` | anyone | Cinema details |
| GET | `/api/movies/` | anyone | Filters: `status`, `genre`, `q`, `showing=upcoming` |
| GET | `/api/movies/<slug>/` | anyone | One movie |
| GET | `/api/movies/<slug>/poster.svg` | anyone | Generated poster |
| GET | `/api/genres/`, `/api/halls/`, `/api/seat-types/`, `/api/ticket-types/` | anyone | Reference data |
| GET | `/api/showtimes/` | anyone | Filters: `date`, `movie`, `hall`. Defaults to the next 14 days |
| GET | `/api/showtimes/<id>/seats/` | anyone | Seat map with live availability and prices |
| POST | `/api/auth/register/` | anyone | Create an account, returns tokens |
| POST | `/api/auth/token/`, `/api/auth/token/refresh/` | anyone | Sign in, refresh |
| GET, PATCH | `/api/auth/me/` | user | Profile |
| GET, POST | `/api/bookings/` | user | Own bookings (staff: all, with customer and payments). Body: `{"showtime": 1, "seats": [{"seat": 10, "ticket_type": "adult"}]}`. Staff filters: `q` (reference or email), `status`, `date`, `showtime` |
| POST | `/api/bookings/<id>/checkout/` | user | Start paying |
| POST | `/api/bookings/<id>/cancel/` | user | Cancel, with a refund if paid. Customers up to 2 hours before the show |
| GET | `/api/payments/config/` | anyone | Active provider and its public key |
| POST | `/api/payments/stripe/webhook/` | Stripe | Payment outcomes |
| POST | `/api/tickets/<code>/check-in/` | staff | Scan a ticket at the door |
| GET | `/api/admin/summary/` | staff | Seats sold, takings and check-ins for a day (`date`), per screening |
| POST, PUT, PATCH, DELETE | `/api/movies/`, `/api/showtimes/` | staff | Manage the programme. Films and showtimes with bookings cannot be deleted, and a showtime cannot change screen once seats are booked |

## Maintenance

`manage.py release_expired_holds` frees expired holds. Seat maps already do it when they are read; schedule it with cron to keep booking lists tidy.
